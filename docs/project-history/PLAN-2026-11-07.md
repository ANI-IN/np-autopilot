## Addition 1: Phase 5 is the Claude plugin platform (foundation + one example plugin)

- **One MCP server** as the gateway to the core: graph queries, search and retrieval
  with slide/page/section/timestamp citations, record operations, program/schedule
  queries. Built on `mcp_server/kb_server.py` and the same service layer as the web
  API; well-described tools, consistent outputs, provenance in every response.
- **Claude.ai remote access:** the server over HTTPS (Vercel alongside the app, or
  elsewhere: to be proposed) with OAuth sign-in through IK Google accounts; every user
  acts as themselves under row-level security; drafts and restricted data never leak.
  Follow the current Claude docs for remote MCP / custom connectors.
- **Claude Code:** the same server, locally or remotely; keep `ikkb_` tokens for scripts.
- **Plugins** are Claude plugins with skills that use the MCP tools. Plugin logic lives
  in the plugin, never in the core; adding one needs no core change. Packaged for the
  organization's internal plugin catalog, not the public repo; documented build and publish steps.
- **Audit log** (append-only) of tool calls and data access per user.
- **One example plugin end to end:** Knowledge Search or Curriculum Builder (recommend one).
- **Design note** mapping future plugins (Curriculum Builder, Knowledge Search, SME
  Discovery, KYP Intelligence, Curriculum Audit, Resource Reuse, NP Workflow) to MCP
  tools and the data each still lacks.
- Review the existing `ik-knowledge-assistant` plugin and fold it into this structure.

## Addition 2: plan improvements

1. **Go-live checkpoint after Phase 2:** plan and rehearse a production release of the
   cleaned-up, faster version (GO_LIVE.md, a production backup first, the owner's
   explicit approval at each irreversible step). Later phases ship in smaller releases
   so DEV and production don't drift apart.
2. **Production readiness:** production Supabase is on a Free organization with no
   backups and the Vercel team appears to be Hobby. Check current plan terms (backups,
   pausing, commercial use, function limits); list required plan changes and costs;
   add them to the GO_LIVE checklist.
3. **Scheduled runs:** where the change detector and headless Claude Code extraction
   run reliably (not a laptop that sleeps); check Claude plan terms for unattended
   headless use; include a fallback.
4. **Quality evaluation:** before the full crawl, a test set of 30–50 real queries with
   expected results (RAG evaluation presentations, a practical MCP demo, Backend
   assignments on distributed systems, System Design interview material, multi-agent
   orchestration slides); score the pilot (precision, citation accuracy, misses);
   re-run after every extraction or search change.
5. **Before Phase 4:** steps to make the GitHub repo private, and confirmation that
   nothing in deployment depends on it being public.
6. **After Phase 1 and Phase 3:** a 10-minute test script for 2–3 NP team members on
   the top tasks, plus a short form to capture what confused them.
7. **Monitoring:** alerts (email or Slack) for failed syncs, failed extractions,
   ingestion errors and server errors; credential expiries tracked in HANDOFF.md with a
   reminder two weeks before each.
