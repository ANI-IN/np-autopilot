# np-autopilot — pinned dependencies.
#
# requirements.txt rather than pyproject.toml, deliberately:
#   1. Nothing here is installable or importable as a package. The pipeline runs
#      from a checkout, and `pipeline/` is reached via sys.path, not an entry
#      point. pyproject.toml would declare a build backend nobody builds.
#   2. The only job is reproducing an environment, and `pip install -r` does
#      exactly that with no extra machinery. AUDIT §6.8 was "a teammate cannot
#      reproduce the environment from the repo" — this is the smallest thing
#      that fixes it.
#   3. If the plugin ever ships as a package, or tool config (ruff, pytest)
#      needs a home, pyproject.toml becomes the right answer. It is not yet.
#
# Exact pins, not ranges. This is an application environment, not a library:
# a silent minor bump in openpyxl changes how the corpus parses, which is a data
# correctness question, not a dependency-resolution one.
#
# Verify:  python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
#          .venv/bin/python -m pytest tests -q
